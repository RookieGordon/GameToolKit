## 3 行为正确性

### 3.1 运行时复现的缺陷（独立探针，全部可确定性重现）

探针为临时工程（引用 `ToolKit/Tools/Tools.csproj`，ImmediateExecutionContext，复现后已删除），复现步骤与代码位置如下，交回大肥鱼修复。

**P1（=SUP-05，P1）：无人接收的产物释放后仍留在复用索引，同键新请求领到已释放产物**
- 复现：加载器返回 `Product` 产物；以 `<string>` 请求同键 → 交付时类型不符只让该项失败 → `delivered==0` → 产物被释放；随后以 `<Product>` 请求同键。
- 实测输出：首次失败码 `asset.type_mismatch`、旧产物 `Released=True`；**新请求 `Value == 已释放的旧产物 == True`，后端加载次数 = 1（未重新加载）**。
- 根因：`ResourcePipeline.cs:440-445` 无人接收只调 `entry.Detach()`——它只清 `_registered` 标志（`ResourcePipeline.cs:940`）；真正的复用索引是 `ResourceStore._current`，`TryGetLive`（`ResourceStore.cs:54-66`）不看该标志。`_Terminate`（`ResourcePipeline.cs:480-491`）也不从容器移除该条目。
- 契约依据：《最终结果文档》§3"本轮产物若已登记却无人接收，必须从可复用集合撤下……否则后续命中它就会交付一个已死对象"。测试《无人接收的迟到产物…不留下复用项》只断言了 `late.Released`，**没有验证复用索引**，测试名超出其实际覆盖。

**P2（=SUP-09，P1）：业务卸载释放未完成时退出，同一产物 ReleaseAsync 被启动两次**
- 复现：产物释放回调内阻塞；`UnloadUnusedAsync` 进入释放后调用 `manager.Dispose()`。
- 实测输出：**ReleaseAsync 实际启动次数 = 2**。
- 根因：`ResourcePipeline.cs:614` `TryBeginUnload` 返回值被忽略；`ResourcePipeline.cs:629-634` 对全部条目无条件再启动 `_RunUnloadAsync`。违反《最终结果文档》§6.1"ReleaseAsync 由框架至多启动一次"。

**P3（=SUP-15，P1）：池创建开始后取消，租用调用永久悬挂**
- 复现：工厂 `CreateAsync` 内阻塞并忽略取消令牌；租用后取消调用者令牌；再放行工厂令其晚返回实例。
- 实测输出：取消后 3 秒租用未返回；**放行工厂后 5 秒仍未返回**（永久悬挂）。
- 根因：排队取消回调对已开始（`Started`）的请求直接返回（`InstancePool.cs:906-912`）；`_CompleteCreate`/`_CompleteReuse` 对已取消/已关闭只销毁实例、**不完成请求的 TCS**（`InstancePool.cs:301-319`、`:170-183`）→ 等待者的 `TaskCompletionSource` 无人置位。

## 4 可读性

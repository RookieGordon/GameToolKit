# 资源系统重写实施方案

现行设计，更新于 2026-10-13。资源请求由业务产生，`LoadManager` 合并同键请求并安排加载任务，加载器执行具体加载，完成时一次建立各请求的独立持有。已经加载的产物、下载文件、池中实例分别管理。资源容量与回收时机由业务决定；框架检查持有关系、执行显式卸载，把释放失败的具体残留移入独立脏集合。

本文件统一描述现行流程、职责、接口和实现约束。生产者—消费者改造前的多轮方案与本次卸载职责收紧前的方案均保存在[历史目录](历史/说明.md)，仅用于追溯，不与本文件叠加执行。

## 1 需求边界与设计模式

| 需求 | 实现边界 |
|---|---|
| 统一加载、释放、池化和缓存 | 业务使用 `LoadAsync`、`RentAsync` 及各自凭证；来源显式指定 |
| 支持 Resources、AssetBundle、本地、远端 | 每个 `ResourceSource` 直接对应一个加载器，不经名称二次映射 |
| 用户可替换加载实现 | 组装时可替换；运行时可新增未注册来源，不支持已有来源热替换 |
| 不限制项目目录或清单形式 | 地址由具体加载器解释；AssetBundle 的包与依赖生命周期由接入方管理 |
| 内存回收由业务决定 | 核心不设置内存容量、估算字节、LRU 或资源 TTL；提供按范围卸载及结果反馈 |
| 清理异常隔离具体对象 | 实际残留进入脏集合，不占正常键索引、不自动重试、不封锁后续请求 |
| 远端优先复用本地文件 | 有效缓存命中直接返回路径，未命中才调用填充方法下载 |
| 防止下载文件长期堆积 | 启动时扫描并按容量目标尽力删除；运行期无定时删除、容量硬上限或文件租约 |
| 独立取消与明确失败范围 | 单个请求取消不取消其他请求；本地共同失败、远端后继继续尝试由注册策略指定 |
| 简单且可维护 | 从流程确定职责；不为模式补空壳，也不把所有动作都包装成队列任务 |

主协作模型是**生产者—消费者**：业务产生资源需求，`LoadManager` 产生实际加载任务，加载器消费任务。消费者表示异步执行角色，不意味着另建线程。缓存命中与引用归还直接按职责处理。

辅助采用 GoF 的**策略、外观、适配器**，与主模型共 4 个：策略用于加载器和转换实现替换；外观由 `ResourceManager` 提供统一业务入口；适配器把 Unity、第三方资源框架和下载工具接入已有接口。生产者—消费者不属于 GoF 23 种。其他模式不增加独立结构，模式选择服从主流程。

不在当前范围：同步加载、通用场景加载、插件发现与热插拔、严格磁盘配额、内存预算与自动淘汰、AssetBundle 卸载与依赖管理、自动恢复清理故障、等待全部业务归还的管理器关闭协议。

## 2 主流程与职责

### 2.1 加载主线

**路由与解析 → 查可复用产物 → 命中即交付，未命中合并或入队 → 消费执行 → 一次提交全部引用或失败 → 结束临时操作。**

```mermaid
flowchart TD
    A[LoadAsync 请求] --> B[检查初始化与退出 标识来源并解析身份]
    B --> C{在执行上下文查询同键记录}
    C -->|有效产物| R[验证类型 增加持有 返回独立引用]
    C -->|旧产物失效| D[撤下复用索引 保留旧对象与原引用]
    C -->|真正卸载中或旧操作正在收尾| W[等待实际结束 成功失败均解除等待]
    W --> B
    C -->|没有产物| O{存在可加入任务}
    D --> O
    O -->|是| J[加入该任务的请求列表]
    O -->|否| N[建立 LoadOperation 放入来源队列]
    N --> J
    J --> Q{有可用并发额度}
    Q -->|否| H[等待已有消费者取走队首任务]
    Q -->|是| L[退出登记委托后 调用加载器]
    H --> L
    L --> S{加载成功且有有效请求接收}
    S -->|是| P[一次提交建立独立引用并交付]
    S -->|否| U[本轮负责未交付产物的收尾 按策略完成请求]
    U --> F[实际残留加入脏集合 临时操作退出]
    P --> E[临时操作退出 消费者继续取任务]
    F --> E
```

每个业务调用是一份请求，同一身份的多个调用可以对应一份实际加载任务。请求等待自身完成任务，不排进“逐个取得执行权、再领取资源”的第二条队列。查询旧产物失效不会触发释放，不等待旧引用归还；业务明确开始的卸载和已经放弃的原生操作，仍须观察实际结束。

### 2.2 角色与数据归属

| 类型 | 保存的事实和承担的职责 | 不承担的职责 |
|---|---|---|
| `ResourceManager` | 初始化、公开入口、超时与用户取消归类、工厂入口、退出释放 | 具体资源定位和加载算法 |
| `LoadManager` | 路由、请求合并、来源队列、执行及批量交付、业务卸载编排、脏集合 | 内存预算、自动淘汰、HTTP、清单、包卸载 |
| `LoaderRegistration` | 来源、加载器、策略快照、`PendingLoads` 队列及 `ActiveLoads` 数量 | 业务持有和底层资源 |
| `LoadOperation` | 一次待消费或执行中的任务、固定解析结果、请求列表、操作取消、收尾完成信号 | 已交付产物的长期存储 |
| `PendingResourceRequest<T>` | 单次调用的类型、进度、取消令牌和 `TaskCompletionSource<ResourceRef<T>?>` | 底层共享操作所有权 |
| `ResourceStore` | 具体产物集合、当前复用索引、引用计数、存活查询 | 容量统计、LRU、淘汰决定、加载或卸载调度 |
| `ResourceEntry` | 实际产物、持有数、失效事实、卸载状态及完成通知 | 保留策略、请求、解析输入、加载器依赖 |
| `DirtyResource` | 释放失败的具体对象、资源身份与诊断 | 正常复用、按 key 准入控制、自动释放重试 |
| `ResourceRef<T>` | 对一份具体 `ResourceEntry` 的独立持有 | 按地址重新绑定新一代产物 |
| `InstancePool` | 原型引用、实例创建与租用编排、池代际、归还和销毁 | 通用资源加载算法 |
| `FileCache` | 完整文件路径复用、一次填充、校验、启动清理 | URL、HTTP、下载重试、转换 |

### 2.3 身份与所有权

- `ResourceKey = ResourceSource + ResolvedResource.LocalKey`。核心按 Ordinal 比较，不猜路径、不删查询参数、不改小写。影响内容、版本、表示或释放规则的参数必须由加载器纳入身份。
- `ResolvedResource.Payload` 仅由选中的加载器解释，作为本次执行快照；不能携带需要核心释放的未交付资源。
- 成功返回 `LoadedAsset` 是加载器向框架交出产物管理及约定释放责任的边界。此前失败由加载器回退中间资源，回退失败则在异常中交出具体残留；此后由框架至多调用一次释放回调。未转交所有权的 AssetBundle 资产没有释放回调，框架不因取得资产而推断自己拥有包。
- 成功完成请求任务是框架向调用者交付引用的边界。先增加持有，再完成任务；成功后发生的取消不能丢弃已经分配的引用。
- 临时任务在成功交付或失败通知完成后移除。无人接收、无效产物或取消后的迟到产物，必须由原操作完成释放后再退出，不能留给下一次请求补救。
- `ResourceRef<T>` 与 `InstanceLease<T>` 都是非池化的引用类型，Dispose 幂等，释放后的外部凭证永久失效。

## 3 公共接口与扩展契约

### 3.1 业务入口

```csharp
public sealed class ResourceManager : IDisposable
{

        RequestOptions? options = null, CancellationToken cancellationToken = default) where T : class;
    public Task<InstanceLease<T>> RentAsync<T>(string address, ResourceSource source,
        string? factory = null, RequestOptions? options = null,
        CancellationToken cancellationToken = default) where T : class;

    public Task<ResourceUnloadResult> UnloadUnusedAsync(
        Predicate<ResourceRow>? select = null, CancellationToken cancellationToken = default);
    public Task ClearPoolAsync(string address, ResourceSource source, string? factory = null,
        CancellationToken cancellationToken = default);
    public void Tick();
    public ResourceSnapshot GetSnapshot();
    public bool IsInitialized { get; }
    public bool IsDisposed { get; }
    public void Dispose();
}

public sealed class ResourceRef<T> : IDisposable where T : class
{
    public T Value { get; }
    public bool IsValid { get; }
    public ResourceRef<T> Retain();
    public void Dispose();
}

public sealed class InstanceLease<T> : IDisposable where T : class
{
    public T Value { get; }
    public bool IsValid { get; }
    public void Dispose();
}
```

`source` 必填，枚举为 `Resources / AssetBundle / Local / Remote`，不存在默认来源。`factory == null` 使用配置中的默认实例工厂。注册来源重复报错；`ReplaceLoader` 仅限初始化成功前。业务调用前须等待唯一初始化任务成功，加载入口不偷偷初始化。

`RequestOptions` 包含 `Timeout`、`Progress`、`Parameters`。超时覆盖整个调用的解析及等待；null 继承系统设置。参数在调用期间保持不变，核心不解释其内容。未知总量的进度使用 `TotalBytes = null`。

### 3.2 加载器

```csharp
public interface IResourceLoader
{
    Task<ResolvedResource> ResolveAsync(ResourceRequest request, CancellationToken cancellationToken);
    Task<LoadedAsset> LoadAsync(ResolvedResource resource,
        IProgress<ResourceProgress> progress, CancellationToken operationToken);
}

// ResourceRequest: Source, Address, RequestedType, Parameters
// ResolvedResource: LocalKey, RepresentationType, Payload
// LoadedAsset: Value, IsAlive, ReleaseAsync
// new LoadedAsset(value, isAlive: ..., releaseAsync: ...)；无底层释放责任时省略 releaseAsync
```

`ResolveAsync` 将业务地址解释为身份和执行输入，支持异步查询或加载器自己的清单缓存。它不加载并交出最终对象。`LoadAsync` 接收整个操作的独立取消令牌，不能把首个请求的个人令牌用作共享加载生命周期。

`LoadedAsset.IsAlive` 是无副作用的存活查询；Unity 实现使用 Unity 对象的存活语义。`ReleaseAsync` 按产物拥有者的释放契约完成。Unity 图片转换器的 `Destroy` 正常返回表示销毁请求已接受，不能因帧末之前仍存活就误报失败；GameObject 实例工厂仍等待实际销毁，以保护实例依赖的原型。第三方资产如何释放不由核心根据类型猜测。

同键必须提供兼容的产物与释放语义。释放回调只处理它捕获的具体对象，不按地址重新查找后来的产物。Resources 的失败旧对象可能在后续请求中重新取得，因此脏集合不得自动重试卸载。AssetBundle 生命周期由外部所有者处理，不加入核心释放故障判断。

### 3.3 实例工厂与文件转换

```csharp
public interface IInstanceFactory
{
    ResourceRequest GetPrototypeRequest(ResourceRequest instanceRequest);
    string GetInstanceKey(ResourceRequest instanceRequest);
    bool CanCreate(object prototype, Type instanceType);
    Task<object> CreateAsync(object prototype, ResourceRequest creationRequest, CancellationToken operationToken);

    void OnReturn(object instance);
    Task DestroyAsync(object instance);
}

public interface IFileResourceConverter
{
    Task<LoadedAsset> ConvertAsync(string path, Type resultType, string? conversionKey, CancellationToken ct);
}
```

工厂同步回调可能执行用户脚本，返回后须复查池、请求及管理器状态。重置失败的实例销毁；销毁失败保留隔离记录及原型。`OnRent/OnReturn` 不阻塞，不在返回后异步改变实例所有权。

转换器只将文件转换为目标对象，失败时回退中间对象；回退失败通过 `ResourceLoadException.CleanupRemainders` 交出实际残留，不只留下一个 Unknown 状态。`FileResourceConverters` 是一张 `Type → IFileResourceConverter` 表，精确注册及查询，重复类型报错；不通过名称、遍历试探或文件后缀猜测实现。同一个本地或远端加载器支持多个目标类型。

### 3.4 业务卸载与脏集合

```csharp
public sealed class ResourceUnloadResult
{
    public int ReleasedCount { get; }
    public int SkippedInUseCount { get; }
    public IReadOnlyList<DirtyResource> Failures { get; }
}

public sealed class DirtyResource
{
    public ResourceKey Key { get; }
    public LoadError Error { get; }
    public IReadOnlyList<object> RetainedObjects { get; }
}

// ResourceSnapshot: ResourceRows, PoolRows, DirtyResources,
//                   IsInitialized, IsDisposed
// ResourceRow: Key, State, HoldCount, WaitingCount
// ResourceLoadException: Error, CleanupRemainders
```

`UnloadUnusedAsync` 的 select 接收资源快照，null 选中全部资源；它不匹配 FileCache 磁盘文件。框架只释放选中且实际执行前无人持有的具体产物，跳过在用项，汇总成功数和失败对象；取消只停止调用者等待，已发起的释放继续收尾。

`GetSnapshot().DirtyResources` 可用于排查具体残留。集合不安排自动重试，不提供“按旧 key 清掉后来产物”的操作。隔离允许继续加载，但不会消除残留的 native/GPU 内存占用。框架不负责为业务选择回收时机，也不再提供估算内存预算。

## 5 加载算法与时序

### 5.1 缓存查询与请求登记

缓存查询、命中时增加持有、未命中时登记请求在同一次执行上下文提交中完成，不能先查再在另一次提交里登记。加载前不扫描脏集合，也不负责清理旧资源。

| 发现的事实 | 本次动作 |
|---|---|
| 存在有效产物 | 验证请求类型，创建独立引用，直接完成 |
| 旧产物失效 | 标记具体记录失效，撤下当前复用索引，继续新加载；旧引用仍绑定原对象 |
| 业务已经开始卸载当前产物 | 等待其 RemovalTask 真实完成，再重新查询；释放失败同样解除等待 |
| 旧加载已放弃，实际操作仍未收尾 | 等待 Finished，新请求不加入 |
| 已有可加入的 LoadOperation | 只添加本请求 |
| 没有可复用产物、没有加载 | 建立任务并放到该来源的 FIFO 队列 |

普通加载在必要等待结束后重新 Resolve，允许版本已改变；池原型使用建桶时固定的 `ResolvedResource`。旧记录脱离复用索引后仍在具体产物集合中，等业务卸载；旧卸载完成只能移除旧记录，不能误删后来登记的同键产物。

### 5.2 共享成功与独立取消

```mermaid

    A->>M: 解析并提交请求
    M->>Q: 未命中 建立一份任务
    M->>L: 离开登记委托后执行 LoadAsync
    B->>M: 同键请求
    M->>M: 加入同一任务
    opt A 在交付前取消
        A->>M: 取消自己的请求
        M-->>A: OperationCanceledException
    end
    L-->>M: LoadedAsset
    rect rgb(235, 245, 250)
        M->>S: 登记一份产物
        M->>S: 为未取消且类型匹配的请求增加持有
        M-->>B: 完成任务并交付 ResourceRef
        M->>M: 移除临时加载任务

```

`MaxConcurrentLoads` 限制每来源同时执行的实际任务，默认 4，0 表示不限制。一个同键任务只占一个位置。每次生产最多新增一份任务，因此入口最多领取并启动一个消费者；已有消费者执行完本轮、成功批量交付或完成失败收尾后，再取下一份。接续任务前 `await Task.Yield()`，切断前一个后端同步完成或取消回调的调用栈，不递归启动。它不承担专属线程、全局优先级、公平调度或持久化任务的保证。

同键实际加载由阶段登记协调：加载时保留唯一操作，当前产物供直接复用；业务卸载当前产物时保留其完成通知直到实际释放结束。失效旧对象从复用索引分离后允许出现同键新对象，两者以具体记录区分。`LoadManager` 不再叠加同键异步锁；通用 `KeyedAsyncLock` 组件继续供其他需要独立异步互斥的模块使用。

```text
AcquireReference(request):
    repeat:
        检查调用者取消
        resolved = Resolve(request)              // 池入口提供固定结果
        在上下文中:
            检查退出
            有有效产物 → 验证类型、增加持有、返回新引用
            旧产物失效 → 撤下复用索引，不执行清理
            当前产物卸载中或旧加载仍在收尾 → 获取完成任务
            否则:
                找到同键操作，或建立操作并加入来源队列
                添加本次请求
                有可用并发额度时取出一份待执行操作
        需要等旧状态 → 可取消地等待实际结束，再 repeat
        登记个人取消处理
        在登记委托之外启动已取出的一个消费者
        reference = 等待本请求 Completion
        reference 非空 → 返回引用
        收到重试信号 → repeat

    while operation 存在:
        await ExecuteAndComplete(operation)
        在上下文中归还额度，并从同来源队首取得下一份任务
        有下一份任务 → await Task.Yield()，异步接续后再执行

ExecuteAndComplete(operation):
    使用操作令牌调用 Loader.LoadAsync
    在上下文中:
        失败 → 隔离异常携带的具体残留，按失败策略通知，移除操作
        成功且有效且操作未放弃:
            登记 ResourceEntry
            对所有请求分别判断个人取消和类型
            为可交付请求增加持有并完成其任务
            有持有者 → 移除操作并结束
            无持有者 → 撤下产物，仍由原操作暂管
        无效产物、已放弃或退出 → 标记本操作正在收尾
    若产物无人接收:

```

在成功任务完成后不能再加一层“可取消等待”而丢掉已交付的引用。交付阶段不重新解析、不清理上一轮对象，也不自动重载；每个请求的类型不兼容只使该请求失败，不阻止其他兼容请求取得引用。

### 5.3 失败、重试与全部放弃

| 条件 | 请求完成方式 |
|---|---|
| `FailWaitingRequests` | 同轮仍在等待的请求共同失败；后续新请求可重新尝试 |
| `ContinueWaitingRequests` | 发起本轮尝试的请求失败；其他未取消请求收到重试信号，重新解析后合并下一轮 |
| 清理失败且带有实际残留 | 先记录脏对象，再按本轮失败策略通知；不永久封锁同键 |
| 仅有 Unknown 或 Incomplete 标记，没有实际残留 | 保留错误诊断，不制造空脏对象，不改变后续准入 |
| 单个请求取消或超时 | 只移除此请求；其余请求仍可接收本轮结果 |
| 所有请求放弃且任务仍排队 | 从来源队列移除任务，无须调用加载器 |
| 所有请求放弃且任务已执行 | 取消操作令牌，保留该操作直到后端真实结束，释放迟到结果 |

失败策略由注册配置决定，核心不根据 Local/Remote 名字推断。Unity 宿主注册远端文件加载器时明确使用 ContinueWaitingRequests；单独注册时应显式设置所需策略。这里的后继尝试不代表自动无限重试原失败请求，也不把 Resources 加载失败直接解释为资源文件损坏。

取消分为两步：上下文内移除请求并标记操作放弃；离开提交委托后才通知底层取消令牌。取消回调可能让加载立即同步完成，不能把它当成不会执行外部逻辑的字段赋值。退出时也遵循这一顺序。

## 6 引用、缓存与业务卸载

### 6.1 归还与保留

`ResourceStore` 管“存着哪些具体对象、谁还在用”，业务管“还要不要留着”。最后一个引用归还只把记录改为 Idle；核心不按容量、时间或估算字节自动卸载。`Tick` 只维护实例池。下载文件的启动清理保持独立，不因为内存策略收缩而改变。

```mermaid
stateDiagram-v2
    [*] --> Ready: 成功提交并分配引用
    Ready --> Idle: 最后引用归还
    Idle --> Ready: 产物有效且再次获取
    Idle --> Unloading: 业务选中且无人持有
    Ready --> Unloading: 进程退出接管
    Unloading --> Removed: 释放完成
    Unloading --> Dirty: 释放失败 残留移入独立集合
    Dirty --> [*]: 正常索引移除 不重试旧释放
    Removed --> [*]
```

`Loading / Draining` 来自临时任务的诊断投影。Dirty 是独立集合，不是 `ResourceState` 值，也不参与后续加载准入。产物失效只撤下复用索引，不触发上图的 Unloading；仍保留原条目和引用，直到业务卸载或进程退出。

```text
Release(reference):
    外部凭证原子置为已释放，重复调用结束
    当前已在执行上下文 → 立即对绑定的具体条目减少持有
    其他线程 → Post 回上下文减少持有
    持有归零 → 标记 Idle

UnloadUnused(select, callerToken):
    在上下文中取得具体产物及 ResourceRow 快照
    离开状态提交后执行业务 select；null 表示全选
    回到上下文，逐个复查当前引用数量:
        已移除 → 跳过
        仍有持有 → 计入 SkippedInUseCount
        已在卸载 → 加入其完成任务
        无人持有 → 标记 Unloading，登记本次释放
    离开提交后启动各项 ReleaseAsync
    等待实际结果，汇总 ReleasedCount 与 Failures
    调用者取消只停止等待，已开始的释放仍收尾

Unload(entry):
    await 这份具体产物的 ReleaseAsync
    在上下文中:
        失败 → 保存 DirtyResource 和实际残留，报告诊断
        成功失败都移除这份旧条目，完成 RemovalTask
        不能按 key 删除后来产生的新条目
```

### 6.2 业务调用与失败隔离

```csharp
// 退出玩法后先结束实例使用，再归还资源持有，最后选择本次卸载范围。
lease.Dispose();
await resources.ClearPoolAsync("enemy", ResourceSource.AssetBundle, cancellationToken: ct);
var result = await resources.UnloadUnusedAsync(
    row => row.Key.Source == ResourceSource.Remote,
    cancellationToken: ct);
// result.ReleasedCount / result.SkippedInUseCount / result.Failures
var leftovers = resources.GetSnapshot().DirtyResources;
```

在 Unity 主线程连续调用 `reference.Dispose()` 和 `UnloadUnusedAsync()` 时，归还立即记账，本次卸载能看到引用已归零；其他线程的归还通过执行上下文投递。业务选择器不在内部状态提交中运行；它可能重新取得资源，故卸载前必须再次检查引用。选择器只决定本次范围，不成为常驻的内存策略注册点。释放某项失败不阻止其他已选项完成；重复卸载调用可以观察同一实际释放的结果，不重复启动回调。

脏集合保存明确失败的旧对象及诊断，不自动修复。若异常没有显式 `CleanupRemainders`，释放阶段保留 `LoadedAsset` 及其值，以免丢掉释放回调闭包中仍被持有的 native 对象；不会再次调用该回调。转换器能指出具体失败对象时，只保留这些对象。保留残留会继续占用内存，这是隔离的代价，不能描述成已经回收成功。

Resources 卸载失败不等于加载失败；后续可能取得相同底层对象。因此绝不能由脏集合后台重试旧卸载。转换器每次创建独立的 Texture/Sprite，旧对象清理失败后可以继续创建新对象。框架不处理 AssetBundle 卸载结果。

## 7 实例池与绑定

### 7.1 租用主线

`PoolKey` 由原型 `ResourceKey`、工厂名和 `InstanceKey` 组成。工厂可以把业务请求映射到不同来源的原型。每桶持有一份原型引用；后续同桶请求不能改变建桶时的解析结果和 `CreationRequest`。

```mermaid
sequenceDiagram
    participant R as ResourceManager
    participant P as InstancePool
    participant M as LoadManager
    participant F as IInstanceFactory
    R->>F: 请求原型描述与实例差异键
    R->>M: Resolve 原型
    R->>P: 上下文内 JoinOrRent
    P-->>R: 本请求任务及可选的新桶初始化责任
    Note over R,P: 退出登记委托之后启动初始化
    R->>P: InitializeAsync 固定原型描述
    P->>M: AcquireResolvedAsync
    M-->>P: 原型引用
    P->>F: CanCreate 然后 CreateAsync
    F-->>P: 实例
    P->>F: OnRent
    P-->>R: 登记 Active 并完成独立租约
    R->>P: 归还租约记录的原桶
    P->>F: OnReturn 或 DestroyAsync
    Note over P,M: 桶关闭且实际实例工作结束后归还原型
```

```text
Rent(request):
    选工厂 → 获得原型请求 → 解析固定原型身份 → 计算 PoolKey
    在上下文中 JoinOrRent:
        已有桶 → 添加等待者，尝试交付，返回本请求任务
        新桶 → 登记 Initializing、等待者、业务地址关联
               返回本请求任务和初始化责任
    离开登记委托后:
        若承担初始化 → 启动固定原型获取
    等待本请求租约

    尚未 Open、正在重入 Pump、没有有效等待者或配额不足 → 结束
    有闲置实例 → 检查存活、OnRent、复查状态、登记 Active 后交付
    没有闲置实例且未在创建 → 启动一次 CreateAsync
```

首次租用取消不撤销它已经承担的桶初始化责任，其他等待者可能已经加入。Dispose 或 ClearPool 发生在登记后、初始化启动前，初始化仍须完成取消收尾，不能让 `InitializationPending` 悬挂。

### 7.2 实例与原型保护

实例处于 `Idle / Active / Preparing / Returning / Creating / Destroying` 中任何阶段，原型都不能提前归还。创建和销毁异步操作要观察到真实结束；取消后的迟到实例必须销毁或按合法归还流程处理。存活查询异常不等于确认对象已销毁。

每桶等待者按 FIFO 处理，每桶同时最多一次创建；活跃配额统计 `Active + Preparing + Creating`。空闲实例超量或到期销毁。`ClearPoolAsync` 捕获当时与 `(source, address, factory)` 关联的全部桶代际，关闭后拒绝这些桶的新租用；新租用可创建新代际，旧租约始终归还原桶。

`PoolState` 的 Closing/Closed 是具体池桶的局部关闭过程，与管理器生命周期不同。销毁失败只隔离对应实例，不封锁整个 `PoolKey`；当前池与后续同键池仍可继续创建、租用。

残留实例可能依赖原型，脏记录因此保留一份独立原型引用。这个引用使业务卸载跳过仍被残留依赖的原型，避免通过“隔离”掩盖提前释放。池内没有失败对象充当活跃或闲置实例。关闭过程中发生的失败汇总到 `CloseError`；`ClearPoolAsync` 等初始化、创建、销毁和旧租约归还实际结束后，才返回关闭结果或抛出清理异常。以前已经隔离的失败不成为未来租用或新池的故障屏障。

### 7.3 业务绑定

`ResourceScope` 持有调用者交入的凭证并按逆序释放。`ResourceBinder` 以目标引用及 slot 为键，后发请求替代同 slot 的未完成请求；新资源应用成功后才释放旧持有。取消或失败保留旧显示，主动 Revert 先清除目标属性再释放引用。

`IResourceApplicator.Replace` 要求异常安全：失败时原属性保持原状。同 slot 同步重入受到保护，不把应用失败造成的未知 UI 状态当成功。`InstanceAutoReturn` 仅作为实例租约的自动归还便利层，不创建另一套引用机制。

## 8 文件加载与启动清理

### 8.1 缓存与 HTTP 解耦

```csharp
Task<string> FileCache.GetOrCreateAsync(

    CancellationToken cancellationToken = default);

// FileRequest: FileIdentity + FileValidity + 可选长度/SHA256
```

`FileCache` 不引用 URL、请求头或下载错误类型。`RemoteFileLoader` 将文件请求与下载委托组合；默认复用项目 `SimpleDownloader.DownloadAsync`，HTTP 重试、连接并发和网络超时留在下载工具中，一次共享填充只调用一次 fill。

启动扫描只读文件名、长度等元信息建立路径索引，不把目录里的文件内容全部加载到内存。每次复用仍检查 `File.Exists` 及有效期；源文件在运行期被外部删除时不能仅凭启动索引认定命中。

### 8.2 文件生命周期

```text

    创建专用目录
    扫描本缓存识别的完整文件及临时文件
    删除识别出的临时残留和同身份旧副本
    按完成时间从旧到新尽力删除，直到 StartupTargetBytes 目标
    为保留的最新完整文件建立路径索引

    未完成初始化 → 明确失败，不等待隐藏初始化
    短锁内:
        校验同身份的有效期约定
        有效路径 → 复用候选
        有填充 → 加入共享完成任务
        否则 → 登记一次填充
    锁外启动 fill(唯一临时路径, 缓存生命周期令牌)
    等待期间个人取消不取消共享填充
    每个调用者按自己的长度和摘要声明校验
    返回完整路径

FillAndPublish:
    await fill
    验证临时文件
    同目录改名为唯一完整路径并更新索引

```

文件名由身份摘要、完成时间及随机标识组成；只处理缓存认识的名称，不递归删除业务目录。调用方应为每个活动缓存实例分配独占专用目录，当前没有跨进程目录锁协议。

运行期不删除已交付的完整路径，因此无需文件租约。到期或校验失效后，新填充发布到新路径；旧路径留到下次启动清理。允许运行期超过启动容量目标，真正写满磁盘时报告本地存储故障并尽力删除临时文件。启动删除失败报告诊断，容量目标不是严格保证。

同文件身份为 `Namespace + ArtifactId + Revision + Variant`，与内存目标类型和转换参数分离。不同内容权限上下文必须使用不同身份。有效期为 Immutable 或 ExpiresAfter；同一身份不允许混用冲突的规则。

### 8.3 远端身份与转换

默认远端身份保留影响内容的端口和查询参数；无显式版本时默认 24 小时 TTL。若签名 URL 不同但内容相同，业务提供稳定身份的 requestBuilder 才能共享文件，核心不擅自删除鉴权或查询参数。

内存身份同时包含源文件身份、精确目标类型与 `FileLoadParameters.ConversionKey`。同一文件可转换为多个独立表示。默认转换表注册 byte[]、string；Unity 组装同一个图片转换器为 Texture2D 与 Sprite。转换器在 Resolve 时选定并放入本轮 Payload，加载时不二次路由。

转换失败不自动证明文件损坏，不删除下载缓存。`ConversionKey` 由具体转换器解释并进入内存身份；当前内置转换器使用固定转换行为，不把该字符串当转换器名称。

## 9 Unity 与第三方接入

`UnityResourceHost.Awake` 只组装 `UnityExecutionContext`、共享文件缓存、下载器、转换表和管理器，默认注册 Resources 加载器与 GameObject 工厂。统一 `InitializeAsync` 成功后开放 `Resources/Cache`；`Update` 驱动 Tick。

```csharp
await host.InitializeAsync(manager =>
{
    host.RegisterRemoteLoader();
    manager.RegisterLoader(ResourceSource.Local, new LocalFileLoader(host.FileConverters));
    manager.RegisterLoader(ResourceSource.AssetBundle, projectAssetLoader);
}, cancellationToken: ct);

var icon = await host.Resources.LoadAsync<Sprite>(url, ResourceSource.Remote, cancellationToken: ct);
image.sprite = icon.Value;
// 使用结束时，先断开目标对象对资源的使用，再归还凭证。
image.sprite = null;
icon.Dispose();

var enemy = await host.Resources.RentAsync<GameObject>("enemy", ResourceSource.AssetBundle);
Use(enemy.Value);
enemy.Dispose();
```

### 9.1 AssetBundle 只接入资产加载

`SimpleAssetBundleLoader` 接收自定义 locator，返回不可变 `BundleLocation`：容器标识、版本、包内资产名和 `GetBundleAsync`。Resolve 不打开或持有包；实际 Load 时才向外部所有者取得已就绪的包并调用 `LoadAssetAsync`。位置协议只属于这个具体适配器，不是 `IResourceLoader` 的要求。

```csharp
var loader = host.CreateBundleLoader((request, token) =>
    Task.FromResult(new BundleLocation(
        containerId: "ui", assetName: request.Address,
        getBundleAsync: bundleOwner.GetReadyBundleAsync,
        version: "v1")));
// bundleOwner 是项目自己的包管理实现，负责打开、下载、依赖和生命周期。
```

包的下载、路径、依赖、共享、卸载都由接入方管理。框架不维护 `BundleEntry/BundleLease`，不调用 `AssetBundle.Unload`，也不对包内资产通用调用 Destroy。AB 产物没有释放回调；归还引用只减计数、归零进入 Idle，业务执行卸载时才移除框架记录，不执行 Destroy/Unload；业务保留框架引用不会自动阻止外部卸包，接入方必须按自身使用关系保证包有效。用户可直接替换为项目加载器，无须模仿 BundleLocation 或暴露 catalog/manifest。

### 9.2 Unity 对象的实际清理

| 对象来源 | 清理行为 |
|---|---|
| 框架实例化的 GameObject | 实例工厂 Destroy，并等到实例确认销毁 |
| 文件转换得到的 Texture、Sprite | 图片转换器在主线程分别请求 Destroy；某项失败不跳过其余对象 |
| Resources 可独立卸载的资产 | ResourcesLoader 调用 UnloadAsset，异常交给核心隔离 |
| Resources GameObject/Component 资产 | 移除框架持有；整体回收时机由业务安排，不调用不受支持的单项卸载 |
| AssetBundle 资产与包 | 框架不执行实际释放，由外部所有者管理 |
| 自定义 Native 产物 | 创建者通过 LoadedAsset.ReleaseAsync 定义释放；失败交出具体残留 |

Unity 原生加载请求一旦启动，就观察到实际完成。个人取消已由核心提前通知调用者，加载器不再通过观察器另做一套迟到清理：Resources 迟到产物仍返回核心，核心负责释放并捕获残留；AB 资产仍归外部包所有者。`UnityAsyncOperationAwaiter` 只转换完成通知，不吞清理异常。

图片转换失败先回退已创建对象；Sprite 与 Texture 分别尝试销毁。失败异常保留原始转换原因、关联清理错误和具体残留，正常接受的延迟 Destroy 不算失败。

## 10 线程、初始化与退出

### 10.1 执行边界

状态变更在一个 `IExecutionContext` 内串行提交。Unity 实现绑定主线程，`RunAsync` 跨线程时返回可等待任务，不使用 `ManualResetEventSlim` 阻塞等待。加载器路由使用自己的短同步锁，查询不投递主线程，锁内不调用加载器。

直接 `LoadAsync/RentAsync` 路径先登记后启动实际加载；池登记返回初始化责任，避免同步完成的原型加载仍嵌套在建桶委托内。`ConfigureAwait(false)` 不保证切线程，`RunAsync` 在当前上下文也可内联。消费者不得因此统一包装成 Task.Run。

消费者继续取下一份任务时增加异步交接，保证不沿着前一个操作的同步完成/取消回调栈立即执行下一加载器。这不等同于保证别的线程已经离开所有状态提交；线程归属和状态修改仍由执行上下文约束。

工厂、存活查询与部分通知本来就可能在上下文内运行，允许的同步重入按各模块的状态复查处理。当前没有提供“任何外部回调重入的新请求都延后至最外层提交退出”的通用调度保证，不能把直接入口的验证扩大为该保证。

| 操作 | Unity 调用要求 |
|---|---|
| LoadAsync、RentAsync、UnloadUnusedAsync、ClearPoolAsync | 可任意线程发起，状态提交返回上下文 |
| 注册、InitializeAsync 发起、Tick、GetSnapshot | 主线程 |
| ResourceRef/InstanceLease 的 Value、IsValid，以及 Retain | 在执行上下文访问 |
| 凭证 Dispose、管理器 Dispose | 幂等，可任意线程调用，必要时投递 |
| Unity 对象创建、存活判断、应用、销毁 | 由对应集成实现回到主线程 |

### 10.2 统一初始化

```text
InitializeAsync(configure, callerToken):
    登记唯一初始化完成任务
    首次调用执行 configure
    await 注入的共享 FileCache.InitializeAsync
    再检查 Dispose，成功后开放业务入口
    重复无 configure 的调用等待同一任务
```

个人取消只取消这次初始化等待，不撤销其他调用者的共享初始化；再次提供 configure 报错。初始化失败保持失败事实，不把下一个资源请求变成重试初始化入口。配置在构造或注册时复制为快照，修改原 options 不热更新系统。

### 10.3 进程退出释放

资源管理器跟随游戏进程运行，只有 `IsInitialized` 与 `IsDisposed` 两个独立事实，不以资源是否全部归还或某次异常来改变全局服务状态。

Dispose 立即拒绝新请求、作废凭证并发起释放，不阻塞主线程、不等待业务归还。先取消待加载请求，再等待实际实例创建/销毁收尾，随后释放资源产物；迟到加载结果由其原操作清理。产物退出先在上下文登记待释放记录，离开状态提交后调用释放回调；池的 Closed 在实际操作收尾后才完成，不再维护另一份退出完成信号。局部失败进入脏集合并报告诊断，不阻止无关资源；显式卸载和进程退出都不重新尝试旧脏对象。

文件缓存仍由创建方负责最终释放。Unity 宿主先发起管理器 Dispose，独立等待缓存实际填充及临时文件清理结束，再释放下载器。进程可以在异步操作结束前终止，`IsDisposed` 不表示所有 native 释放已经完成，框架不虚构退出完成保证。

## 11 配置范围

| 配置 | 默认值 | 实际作用 |
|---|---|---|
| RequestTimeout | 30 秒 | 单次资源/实例调用；系统配置 null 表示无默认超时 |
| MaintenanceInterval | 1 秒 | Tick 的实例池维护间隔；不维护资源缓存容量 |
| DefaultFactory | gameObject | 未指定实例工厂时使用；与来源默认值无关 |
| LoaderPolicy.MaxConcurrentLoads | 4 | 每来源的实际消费并发，0 不限制 |
| LoaderPolicy.FailurePolicy | FailWaitingRequests | 同轮失败影响范围 |
| Pool.MaxIdlePerResource | 32 | 每池桶闲置实例上限，0 归还即销毁 |
| Pool.IdleLifetime | 60 秒 | 闲置实例/空池保留时间 |
| Pool.MaxActivePerResource | null | 每桶 Active+Preparing+Creating 配额，0 非法 |
| FileCache.Directory | 必须指定 | 缓存专用目录；宿主默认 persistentDataPath/resource-cache |
| FileCache.StartupTargetBytes | 512 MiB | 仅启动清理目标；null 不按总量删除，0 尽力清空 |

工厂级 PoolPolicy 完整覆盖该工厂的池策略；池的闲置数量与时间只服务于实例复用，不是资源内存预算。`ResourceSystemOptions.Memory`、`LoaderPolicy.Memory`、`MemoryPolicy` 和 `LoadedAsset.EstimatedBytes` 已移除，框架不提供隐含的零容量或资源自动淘汰模式。业务依据自身场景或内存压力调用显式卸载。

负容量或非法时间初始化/注册时拒绝。null 与 0 按上表具体语义使用，不引入“所有 0 都代表无限”的统一隐式规则。下载并发和网络重试属于注入下载器配置，与来源加载并发分别约束各自工作。

## 12 两层错误与诊断

主 API 使用 `ResourceLoadException` 携带不可变 `LoadError`。用户取消抛 `OperationCanceledException`；请求超时返回 `request.timeout`，不伪装成网络错误或用户取消。

| 面向对象 | 数据 | 使用方式 |
|---|---|---|
| 最终用户 | UserErrorCode | 业务本地化为“网络问题”“资源暂不可用”“存储空间不足”等文案 |
| 开发者 | DiagnosticCode、Stage、Context、Cause、DiagnosticId | 识别 URL 无效、DNS、连接、TLS、HTTP 状态、本地 I/O、转换或释放问题 |
| 开发者与故障隔离 | Cleanup、RelatedErrors、CleanupRemainders | 描述本次回退，保留主因、关联失败和实际残留；不作为按 key 封锁规则 |

`CleanupStatus.Unknown=0 / Complete / Incomplete` 表达本次回退或释放是否完成。未分类异常不能默认声称清理完成；只有标记、没有对象时不制造脏记录，也不影响下一次请求。网络事实来自下载器提供的异常与响应，不由核心把所有远端失败概括成 DNS 或 CDN 故障；磁盘写满、文件校验和转换故障保留各自类别。

`IErrorMapper` 在统一对外交付边界决定用户码，不改原始诊断身份。`IResourceDiagnostics` 提供诊断通知，观察者异常不得中断所有权记账。自定义后端可使用独立诊断前缀。旧 `asset.decode_failed` 字符串继续兼容既有日志筛选，源码名称与阶段已使用 AssetConversionFailed、Convert。

## 13 验证与后续修改准则

实现验收分别检查需求、行为、阅读成本。测试通过不单独证明流程简单；从公开入口应能直接读出登记、执行、交付和归还，不再靠等待者逐个获取锁及反查临时操作解释引用安全。

| 场景 | 必须观察到的行为 | 主要现有测试入口 |
|---|---|---|
| 同键成功、多类型请求 | 一次加载，各自独立凭证，不兼容类型独立失败 | ConcurrentLoadPolicyTests、ResourceAcquisitionFlowTests |
| 来源并发、排队取消 | 不超过配置额度，同键不重复排队，全部取消的排队任务不执行 | ProducerConsumerLoadTests |
| 失败策略与清理故障 | 本地共同失败、后继重解析；具体残留隔离，Unknown 不封锁同键 | ConcurrentLoadPolicyTests、ExplicitResourceUnloadTests |
| 交付与取消相邻发生 | 交付前取消无持有；成功后取消不丢引用 | ResourceAcquisitionFlowTests |
| 旧产物卸载和失效 | 失效只撤下复用索引；实际卸载中的等待结束后重查，失败也解除等待 | LoadPreparationTests、ExplicitResourceUnloadTests |
| 业务选择卸载 | 在用项跳过，选择器重入后复查持有，失败不阻止其他项，不自动淘汰 | ExplicitResourceUnloadTests |
| 直接入口同步完成 | Load/Rent 后端启动不嵌套在各自登记委托中 | LoadStartBoundaryTests、RentStartBoundaryTests |
| 取消触发同步完成 | 后端取消通知在取消状态提交之外，不把下一任务启动带入该委托 | ConsumerCancellationBoundaryTests |
| 池取消、清理、代际与回调重入 | 归还原池，销毁失败只隔离实例并保护原型，后续租用正常 | InstancePoolTests、ReviewFixCoreTests、ResourceDisposeTests |
| 启动及退出 | 唯一初始化、配置快照、退出作废凭证，释放失败不关闭无关功能 | ResourceStartupTests、ResourceDisposeTests |
| 远端本地复用与纯文件缓存 | 命中不下载，初始化已完成，运行期不回删完整路径 | FileCacheTests、FileLoaderTests、RemoteFileIdentityTests |
| 文件转换 | 按精确类型选择，复用同一源文件，转换失败不删缓存 | FileResourceConverterTests |
| Unity 与业务绑定 | 主线程操作、替换成功才归还旧持有、自动归还不重复释放 | UnityExecutionContextTests、绑定及 Unity 集成检查 |

## 外部加载器后注册与策略可视化

### 情境与纠正

原始任务要求使用 ResourceSystemConfig 可视化配置 ResourceSystemOptions，并允许自定义实现。
随后用户要求独立 AssetBundle 系统在资源系统初始化完成后注册加载器。
上一轮实现将 Inspector 标为“启动时注册的加载器”，并建议外部来源的并发与超时在注册代码中传入。
用户指出：“Assetbundle loader 不走配置的话，相关配置不就不透明了吗？”

该实现满足了实例后注册，却没有同时满足原来的策略可视化目标。不能从“实例稍后提供”推导出“策略应移到代码里”。

随后曾以专用 ExternalLoaderConfig 表示后注册。用户明确希望用一个开关控制是否在初始化时创建实例，
最终删除该专用类型和类型判断，统一由 LoaderConfig.InitializeOnStartup 控制。

### 当前处理

- `ResourceSystemConfig.cs` 的 `LoaderConfig.InitializeOnStartup` 决定是否创建实例，来源、并发与总超时始终保存。
- 普通 LoaderConfig 可用于仅保存策略；具体配置类型保持原有工厂接口。关闭开关时不检查或使用工厂专属参数。
- `ResourceSystemOptions.cs` 的 `AddExternalLoader` 将策略写入原有 Loaders 表，实例暂缺；普通 AddLoader 仍拒绝 null。
- `ResourceSystem.cs` 保存构造时的策略值快照；未提供实例时不创建 LoadManager，不等待外部系统。
- 后注册省略策略时沿用快照；显式策略仅覆盖本次注册。ResourceManager 不持有配置资产或第二套策略映射。
- 独立包系统的目录、Manifest 等由该系统自行配置；资源系统只显示并实际执行自己的来源策略。

### 检查点

1. Inspector 中声明的外部来源必须经 Config → Options → ResourceSystem 保留其策略；不只在 UI 中显示。
2. 外部来源尚未注册时，仅该来源的加载失败，其他来源与整体初始化仍可正常工作。
3. 同来源后项替换整项配置；不能只跳过外部项而残留此前的启动实例。
4. 配置和 Options 在装配后的修改不影响运行快照；显式覆盖与恢复配置值的优先级必须清楚。
5. 通过实际并发、超时、资产保存重载、后注册及替换测试验证，不以字段映射检查代替行为验证。

### 验证与删减结果

2026-11-03：开关版本在隔离 Unity 6000.6.7f1 工程的 24 项测试全部通过，覆盖策略保存重载、同来源内置/外部切换、
后注册时的并发与超时、显式覆盖后恢复快照、未注册来源隔离、实际 Resources 资产入口、工厂字段启停与旧资产默认行为。

保留同一个配置列表和 Options.Loaders 表，不增加外部来源列表、占位加载器或待注册任务。
删除了专用外部配置类型及其 Inspector 特殊显示，由同一个开关表达创建时机。
运行时仅新增构造期的策略值快照，区别于 LoadManager 本次执行所用的策略；删除它会使后注册丢失配置值，
或迫使注册入口重新读取可变资产。沿用现有加载管理器表与替换/释放流程，无需额外重构其生命周期。
